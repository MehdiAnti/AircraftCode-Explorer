# Project Roadmap

This document records the current project shape, completed work, known limitations, and remaining verification. Update it when implementation or workflow behavior changes.

## Project goal

Maintain a lightweight aircraft explorer with two distinct data views:

- **Aircraft model catalog:** model/manufacturer/type-code records stored in `data/aircraft.json`.
- **Individual-aircraft registry:** aircraft-level records searchable by registration, ICAO24, ICAO type code, and operator.

The user-facing explorer is a static HTML/CSS/JavaScript website. Python remains the repository's data-import, validation, and maintenance toolchain; it is not required just to use the deployed website.

## Current architecture

- `index.html`, `styles.css`, and `app.js` implement the static website.
- `data/aircraft.json` is the model-level catalog.
- `data/airframes.json.gz` is the full compressed individual-aircraft registry.
- `data/registry/` contains gzip-compressed lookup shards grouped by category and two-character normalized prefixes.
- The browser loads the model catalog for catalog search. Individual-aircraft searches fetch relevant compressed shards on demand and decompress them with the browser's `DecompressionStream` API.
- `.github/workflows/opensky-refresh.yml` is a manual workflow that imports the configured OpenSky CSV snapshot, validates generated data, commits the catalog and compressed registry outputs when changed, and prepares a Pages deployment.
- `.github/workflows/pages.yml` deploys the static website and generates compressed registry files for the Pages artifact.
- The configured OpenSky source is a fixed **May 2024 snapshot**, not a live feed. Workflow execution does not make the underlying source data newer than that snapshot.

## Completed project phases

The repository began as a Python model-catalog CLI and expanded into a static website and aircraft-level registry. Historical phases are retained here as a summary rather than a statement that the Python CLI is the primary user experience.

- **Foundation and CLI:** catalog loading, search, statistics, and command-line tooling.
- **Testing and data quality:** standard-library unit tests, CI matrix, normalization, deduplication, and provenance handling.
- **CSV export and catalog inspection:** export, sorting, status/freshness reporting, and review commands.
- **OpenSky import:** CSV-based import path that keeps individual-aircraft records separate from model-level records.
- **Static web explorer:** responsive HTML/CSS/JavaScript interface with model search and individual-aircraft lookup modes.
- **Compressed registry:** full compressed registry and on-demand compressed lookup shards.
- **Refresh and deployment workflows:** GitHub Actions workflows for manual source import and GitHub Pages deployment.
- **Registry storage cleanup:** PR #18 keeps compressed registry files and removes duplicate uncompressed registry copies.
- **Website-first documentation:** README describes the web experience first and places optional Python developer instructions in a collapsible section.

See the merged pull requests and GitHub Actions history for exact commit and check results. Do not infer a successful run from the presence of a workflow file.
